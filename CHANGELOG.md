# Changelog

All notable changes to MeshLink are recorded here, in the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) style. Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as [ADR 0019](docs/adr/0019-release-versioning-and-api-compatibility.md) defines them. Every PR adds its entry under "Unreleased" and states its SemVer impact; `./gradlew check` fails when an ABI dump changes without a change here.

## [Unreleased]

### Added

- Committed ABI dumps for `meshlink` and `meshlink-testing`. Both modules are still empty, so the dumps are empty. SemVer impact: none.
- Maven publishing of `meshlink` with a complete POM under The Unlicense, and the `MeshLinkKit` XCFramework for iOS. The `meshlink` klib dump gains its header and still declares nothing public. SemVer impact: none.
- `meshlink-testing` now depends on `meshlink` and `kotlinx-coroutines-test` and holds the internal `VirtualAir` test radio. Its klib dump gains its header and still declares nothing public. SemVer impact: none.
- The node lifecycle API in `ch.trancee.meshlink`: `meshLinkConfig(preset, securityProfile) { meshId = … }.build()` with mesh ID validation and `describe()`, `MeshLink.create(config, platform)`, suspending idempotent `start()` and `stop()`, final `close()`, and `state` (`Stopped`, `Starting`, `Running`, `Blocked(requirements)`, `Stopping`). `SecurityProfile` holds only `Unsecured`; `Preset` names the five built-in scenarios. One node runs per platform radio; another reports `Blocked(RadioInUse)`. On first start a node creates its Ed25519 installation identity, kept in memory for now. `MeshPlatform.ios()` reports `Blocked(Unsupported)` until the Core Bluetooth radio lands. SemVer impact: minor (new API, pre-1.0).
- Discovery: a running node advertises the 16-byte layout `001` payload with its mesh tag and scans for other members of its mesh, keeping those whose mesh tag matches epoch e − 1, e or e + 1 as link candidates. `peers` stays empty until links land. For `meshlink-testing` only, `MeshLink.linkCandidates()` and `radioFailure()` are `@InternalMeshLinkApi` and hidden from Objective-C, and the internal `PlatformPort` gains `radio` and `clock`. SemVer impact: none (no new public behavior; the additions require the internal opt-in).
- Unsecured links: a running node opens a GATT link to each link candidate, selects the highest common protocol version from the peer's capability record and exchanges `PLAIN_HELLO` in clear records. A peer of another mesh gets `CLOSE` `WRONG_MESH`; two links to one neighbor collapse to the one whose central has the lower NodeId; `stop()` sends `CLOSE` `SHUTTING_DOWN` on every link. New public API: `MeshLink.peers: StateFlow<List<Peer>>`, ordered by NodeId; `Peer` with `nodeId`, `reachability`, `secured` and `lastSeen` (`kotlin.time.Instant`); `Reachability.Direct`; and `NodeId`, which prints as lowercase hex and returns its 32 bytes with `toByteArray()`. A peer leaves `peers` when its last link closes. SemVer impact: minor (new API, pre-1.0).
- Direct messages in `Unsecured`: `MeshLink.send(to, payload)` returns `SendResult.Accepted(OutgoingMessage)` or `SendResult.Rejected(reason)` with `RejectionReason` `NotRunning`, `UnknownPeer`, `TooLarge` (above 4,096 bytes) or `QueueFull` (unwritten payloads at 1 MiB); `awaitSendCapacity()` returns once the queue has room. `OutgoingMessage.status` is a `StateFlow<DeliveryStatus>` of `Queued`, `Held`, `Sent`, `Expired` or `Failed(FailureReason.Stopped)`. Received messages arrive on `messages: Flow<ReceivedMessage>` with the sender's NodeId; a second concurrent collector gets `MeshLinkException.AlreadyCollected`. A message travels only over a direct link to its destination until routing lands, and a message to a known but unlinked peer waits as `Held`. SemVer impact: minor (new API, pre-1.0).
- The Android radio: `MeshPlatform.android(context)` returns the app's one platform, whose Bluetooth LE radio advertises the 16-byte payload (legacy, connectable, 1M, no name), scans for the MESH service, serves the MeshLink GATT service as peripheral, and connects, reads the capability record, subscribes and streams as central. Every GATT request is serialized and retries while the stack is busy, and opening the GATT server retries. Missing Nearby Devices permissions (API 31+) or location permission (API 26 to 30), Bluetooth off, and a phone without Bluetooth LE or its peripheral role show as `Blocked(requirements)`; the requirements are rechecked when Bluetooth changes state and when an activity resumes. MeshLink's manifest declares the permissions; the app requests them. A scan or advertising set that fails after it started now ends discovery as a refusal does. SemVer impact: minor (new API, pre-1.0).
- The iOS radio: on an iPhone, `MeshPlatform.ios()` now returns the app's one platform, whose Core Bluetooth radio advertises the MESH service, scans for it, serves the MeshLink GATT service as peripheral, and connects, reads the capability record, subscribes and streams as central. A connection attempt that hasn't completed after 30 s fails as `PEER_UNREACHABLE`. The Bluetooth prompt can appear at the first `start()`, never at `create()`; the app needs `NSBluetoothAlwaysUsageDescription`. Bluetooth not yet authorized or denied shows as `Blocked(PermissionDenied(Bluetooth))`, Bluetooth off as `Blocked(BluetoothOff)`, and the node stays `Starting` until Core Bluetooth reports its state. The iOS simulator build still reports `Blocked(Unsupported)`. For `meshlink-testing`, the internal `PlatformPort.requirements` is now a `Flow` rather than a `StateFlow`, which changes both ABI dumps. SemVer impact: minor (new behavior, pre-1.0).
- Maven publishing of `meshlink-core` and `meshlink-crypto-sodium` as dependency-only internal artifacts (no API guarantee, outside the SemVer promise), so a consumer that depends on `ch.trancee.meshlink:meshlink` resolves on Android and iOS. `tools/maven-consumer/test.sh` proves it in the macOS CI job. SemVer impact: none.
- A persistent installation identity: the node's Ed25519 seed now survives app restarts. On Android it is sealed with a non-exportable AES-256-GCM Android Keystore key (StrongBox when available) in no-backup storage; on an iPhone it is a `ThisDeviceOnly`, non-synchronizable Keychain item. The iOS simulator build keeps it in memory. A stored identity that can't be read, or a new one that can't be saved, is never replaced: `start()` reports `Blocked(Requirement.IdentityUnavailable)`, `send` returns `Rejected(NotRunning)`, and the next `start()` reads again. The new `MeshLink.resetIdentity()` deletes the stored identity while the node is `Stopped` or `Blocked`, so the next `start()` creates a new NodeId; in any other state it throws the new `MeshLinkException.InvalidState`. For `meshlink-testing`, the internal `IdentityStore` now takes a `CryptoProvider`, may return `null`, and gains `delete()`, which changes both ABI dumps. SemVer impact: minor (new API, pre-1.0).
- Lab apps and tools, never published: `labapp/` holds the scenarios (`direct-message` first) and the Android and iOS host apps; `tools/lab/lab.py` builds, installs and launches them on two lab phones, pulls their JSON Lines results and writes T9 evidence records with pseudonymized Bluetooth addresses. For the lab apps only, `MeshLink.restrictedLinkRole` and `linkRoles` with the new `LinkRole` are `@InternalMeshLinkApi`, which can now mark properties, and hidden from Objective-C; this changes the `meshlink` ABI dumps. SemVer impact: none (the additions require the internal opt-in).
- The internal `CryptoProvider` now has every primitive the `Classical` and `PostQuantum` profiles need: X25519, Ed25519 sign and verify, ChaCha20-Poly1305 (IETF), SHA-256, HKDF-SHA-256, ML-KEM-768 and X-Wing, each key generation and encapsulation also from a seed, with peer-caused refusals as a typed `CryptoResult`. `meshlink-crypto-sodium` binds them on Android and iOS. SemVer impact: none (internal API).
- Tier 2 protocol vectors from a test-only Rust reference in `tools/reference/` (never published): `certificate-signatures.json`, `handshake-hfs.json` and `hpke-seal.json` in `docs/spec/vectors/`, with valid and T10 `invalid` cases. A scheduled, non-required workflow regenerates them and fails on any byte difference. Test-only. SemVer impact: none.

- The internal `IdentityCertificate` in `meshlink-core`: issuing for a node's static keys from the injected `Clock` with a window of at most 24 h, the classical (138 B) and post-quantum (1,354 B) codecs, and validation in the spec's order with a typed `CertificateCheck` whose errors carry the vector codes. It passes the tier 1 `certificate.json`, the `certificate-signing-input` derivation and the tier 2 `certificate-signatures.json`. SemVer impact: none (internal API).
- The internal Noise state machine in `meshlink-core`: `NoiseHandshake` for `Noise_XX_25519_ChaChaPoly_SHA256` and `Noise_XXpsk3_25519_ChaChaPoly_SHA256`, its `split()` into a `NoiseTransport`, and `CipherState` with `Rekey()` and the reserved nonce `2^64 − 1`. Every failure is a typed `NoiseFailure` and closes the handshake or transport. It passes the vendored cacophony vectors for both patterns, handshake and transport. SemVer impact: none (internal API).
- The internal Noise state machine gains the `hfs` patterns with ML-KEM-768, `Noise_XXhfs_25519+MLKEM768_ChaChaPoly_SHA256` and `Noise_XXhfs+psk3_25519+MLKEM768_ChaChaPoly_SHA256`, as the Noise HFS specification defines them. An ML-KEM key that fails the modulus check fails the handshake with `INVALID_PUBLIC_KEY`, and a changed KEM ciphertext fails its tag before decapsulation. It passes every tier 2 `handshake-hfs.json` test byte for byte. SemVer impact: none (internal API).
- `Classical` links: `SecurityProfile.Classical` and the config builder's `meshKey: ByteArray?` (32 B; `null` is an open mesh; redacted in `describe()`; rejected with `Unsecured` as `InvalidConfig("meshKey", …)`). Two `Classical` nodes open a link with a Noise `XX` handshake (`XXpsk3` in a gated mesh) whose prologue binds the capability versions, profile and mesh, verify each other's identity certificate, list each other in `peers` with `secured = true`, and encrypt every later link record. A gated mesh tags its advertisements with the mesh-key tag key. Handshake failures close with `HANDSHAKE_FAILED`; the D-20 bounds (one handshake per bearer, 8 half-open, 10 s, one per address per 2 s) close without a reply. Until end-to-end messages land, `send()` in `Classical` stays `Queued`. For `meshlink-testing`, `MeshLink.linkDiagnostics` with `LinkDiagnostic` (`ML4001`, `ML4002`) is `@InternalMeshLinkApi` and hidden from Objective-C; this changes the `meshlink` ABI dumps. SemVer impact: minor (new API, pre-1.0).
- Spec: the 30 s clock skew applies on both certificate edges, for sealing and every other use; a certificate is usable while `not_before − 30 s ≤ now < not_after + 30 s` (D-46). SemVer impact: none.
- Link fragments: a frame longer than one record crosses a link as `FRAGMENT` (`0x01`) streams, and a receiver out of reassembly slots or budget answers `BUSY` (`0x06`); the sender then retries the message. Reassembly limits follow spec "Fragments": 4 streams per link, 1 large, a 1 MiB large-stream budget per node, a 10 s idle timeout and `frame-max` 139,264 B; each fatal fragment closes the link with `PROTOCOL_ERROR`, and during a secured handshake fails it with `HANDSHAKE_FAILED`. `TooLarge` now starts above 4,096 bytes instead of 899. SemVer impact: minor (pre-1.0).
- `PostQuantum` links: `SecurityProfile.PostQuantum`. Two `PostQuantum` nodes open a link as `Classical` nodes do, with a Noise `XXhfs` handshake (`XXhfs+psk3` in a gated mesh) that adds ML-KEM-768 to X25519, and post-quantum identity certificates (1,354 B) that also bind an X-Wing key. A node never links with a node of another profile. Handshake messages longer than a record (about 1.2, 2.6 and 1.4 KB) cross as cleartext `FRAGMENT` streams. Until end-to-end messages land, `send()` in `PostQuantum` stays `Queued`. This changes the `meshlink` ABI dumps. SemVer impact: minor (new API, pre-1.0).

- Advertisement rotation and resolvable tags: a running node re-advertises a fresh payload once per 300 s epoch at its own random phase, from a new address. In a gated mesh each node holds a daily 32 B resolving key, sends it in the `RESOLVING_KEY` handshake TLV, announces the next one with `RESOLVING_KEY_UPDATE` (`0x0E`) at least an hour before use, and to each new link right after the handshake. Its peers recognize its rotated advertisements by the resolvable tag and don't dial them again. A node holds keys for at most 1,024 peers (spec `resolving-key-peers`). Open meshes and `Unsecured` advertise random tags and recognize a rotated peer only by a new handshake. Link candidates whose mesh tag left the accepted epochs are dropped. For `meshlink-testing`, the internal `PlatformPort` gains `random`, which changes the `meshlink` ABI dumps. SemVer impact: none (no new public API).

- Link limits, flow control and connect retries (ADR 0009 decisions 4, 6 and 7): on a GATT link the central grants the peripheral notification credits with the new link-local `CREDIT` frame (`0x10`, D-47): 8 when the link opens and 4 more after every 4 notifications, so a slow central stalls only its own link; a grant above the window or a `CREDIT` from a peripheral closes the link with `PROTOCOL_ERROR`. A connect that fails with the new `RadioFailure.TRANSIENT` is retried up to 3 times after 500 ms × n, and a link the radio reports lost with `RadioEvent.Disconnected(transient = true)` is reconnected by its central. A radio that reports `RadioPort.peripheralLinkCap` holds at most that many peripheral-role bearers and answers any further one with `CLOSE` `RESOURCE_LIMIT`. `LinkDiagnostic` gains `ConnectFailed` (`ML3003`) and `LinkCapReached` (`ML3004`). The iOS radio reports a cap of 3; the Android radio reports no cap. For `meshlink-testing`, the `LinkDiagnostic` additions change the `meshlink` ABI dumps. SemVer impact: none (no new public API; the additions are internal).

- Rekey: a `Classical` or `PostQuantum` link rekeys each direction with the link-local `REKEY` frame (`0x05`) every 3,600 s on the monotonic clock, and before a key would encrypt more than 65,536 records; a peer that sends a 131,073rd record under one key is closed with `PROTOCOL_ERROR`, and a record under the old key after a `REKEY` closes the bearer. An `Unsecured` node drops a `REKEY`, as it does any unknown link-local frame, with the new internal diagnostic `ML3007 UnknownLinkFrameDropped` (D-48). The internal `LinkCipher` in `meshlink-core` seals and opens link records and counts them; it passes the new tier 2 `link-transport.json` vectors from the Rust reference. The `meshlink` ABI dumps change for the new `LinkDiagnostic`. SemVer impact: none (no new public API).
- L2CAP CoC bearer switch: once a link opens, a central whose peer offers an L2CAP PSM opens a CoC channel and both ends move the link to it with the link-local `BEARER_SWITCH` frame (`0x0F`), in every profile, keeping cipher states and nonces. `BEARER_SWITCH` needs no credit, and a peripheral waits `coc-accept-timeout` (5 s) for the channel, then closes with `PROTOCOL_ERROR` (D-49). A channel that fails to open keeps the link on GATT with the new internal diagnostic `ML3005 BearerFallback`; a lost channel ends the link and the central links again. A node advertises `COC_AVAILABLE` and the `L2CAP_PSM` capability TLV only while its CoC listener is up, and the internal `MeshLink.coc` toggle turns CoC off. `link-transport.json` gains four `BEARER_SWITCH` nonce-continuity vectors from the Rust reference. The `meshlink` ABI dumps change for `BearerFallback` and the `@InternalMeshLinkApi` `coc` toggle. SemVer impact: none (no new public API).
- Android L2CAP CoC adapter: on Android 10 and later the radio listens on an insecure LE CoC server socket, offers its PSM, accepts channels as peripheral and opens them as central, so Android nodes switch links to CoC. Android 8 and 9 report CoC as unsupported and stay on GATT. A failed listener or Bluetooth turning off closes the listener and its channels. A central connect that the stack ends with status 133 or 147 now fails as transient and is retried, and the stack closing an open central link with 133, 147 or 22 is a transient loss that the central reconnects. SemVer impact: none (internal adapter only; ABI dumps unchanged).
- iOS L2CAP CoC adapter and link cap: the Core Bluetooth radio publishes an unencrypted L2CAP channel, offers its PSM, accepts channels as peripheral and opens them as central, so iOS nodes switch links to CoC. A channel's streams run on the main run loop and pass their events to the Bluetooth queue. A channel that doesn't open within 30 s fails, and one that opens later is closed. Listening fails at once while the peripheral manager isn't powered on, and Bluetooth turning off forgets the PSM and closes the accepted channels. The radio now reports `peripheralLinkCap` = 3. SemVer impact: none (internal adapter only; ABI dumps unchanged).
- Proximity, scan windows and background iPhones: each direct `Peer` now has `proximity`, a `Proximity` with the smoothed RSSI in dBm (EWMA, α = 0.25), its `ProximityBucket` (`Immediate` at −55 dBm or more, `Near` at −75 dBm or more, otherwise `Far`, and `Unknown` once the last sample is 30 s old) and when it was measured. It is never a distance and never leaves the node. Samples come from reading the RSSI of each link this node opened, every 10 s, and from sightings of a linked peer. A central now scans in windows of 4 s every 8 s. A sighting without a payload, as a backgrounded iPhone advertises, is dialed to read its advertisement from the capability record; an address whose connect fails, that serves no capability or no advertisement, or that belongs to another mesh is not dialed again until it goes unseen for 10 min. A node advertises `PHY_2M` when its radio supports the 2M PHY. For `meshlink-testing` and the adapters, the internal `Sighting.payload` is nullable, and `RadioPort.supportsLe2MPhy` and `CentralLink.readRssi()` are new; both are abstract, and the platform radios report no 2M support and fail `readRssi()` with `UNSUPPORTED` until tickets 32a and 32b. On iOS, a central link's request exchange moved to the internal `AppleRequests`. This changes the `meshlink` ABI dumps. SemVer impact: minor (new API, pre-1.0).

- Android PHY, scanning and RSSI: from Android 10 a central on a phone that supports LE 2M asks for 2M once connected, and `supportsLe2MPhy` reports it; Android 8 and 9 and phones without 2M send no PHY command. `readRssi` returns the stack's RSSI of a link. Scans filter on the MESH UUID and Apple manufacturer data, and an advertisement holding Apple's overflow area with the MESH bit, in any AD structure, is a sighting without payload; this also finds background iPhones on Android 15 and later, which join a company's manufacturer data into one array. A scan start beyond Android's 5 starts in 30 s is deferred until the oldest start is 30 s old, and stopping cancels it. SemVer impact: none.
- iOS scanning and RSSI: every Core Bluetooth discovery while scanning is now a sighting, and one without the rotating UUID, such as a background iPhone found through the MESH bit in Apple's overflow area, has no payload, so the core dials it and reads the advertisement from the capability record. `readRssi` returns `CBPeripheral.readRSSI`'s value for a link. The core's scan windows restart each iOS scan at least every 10 s, as background scans need. SemVer impact: none.
- Scheduled fuzzing of every decoder, never published: `./gradlew :meshlink-core:fuzz` runs Jazzer 0.30.0 against one target per wire decoder (advertisement, capability record, link records and the record stream, link frames, handshake payload, identity certificate, direct-message frame, message and receipt content, resolving key) from a corpus seeded from the vector files and minimized. `fuzz.yml` runs it weekly and on pull requests that change it, and uploads any crashing input. A host test fails when a decoder in `meshlink-core` has no target. No crash found. SemVer impact: none.
- Neighbor lists: linked nodes exchange `NEIGHBOR_LIST` frames with the identifier they advertise now, the one they will advertise after their next rotation, and their linked peers' identifiers, at most once per 2 s; nothing in them is forwarded. A node advertises exactly the announced identifier at rotation, and its linked peers recognize it by that identifier, so an open mesh no longer redials a peer that rotated. `SHUFFLE` gets an empty `SHUFFLE_REPLY` until views land, and a malformed list or shuffle closes the link with `PROTOCOL_ERROR`. SemVer impact: none (no public API change; ABI dumps unchanged).

### Changed

- Spec: the post-quantum Noise protocol names now follow the Noise specification: `Noise_XXhfs_25519+MLKEM768_ChaChaPoly_SHA256`, `Noise_XXhfs+psk3_25519+MLKEM768_ChaChaPoly_SHA256` and `Noise_IKhfs_25519+MLKEM768_ChaChaPoly_SHA256` (D-45). The names enter the handshake hash, so nodes using the old names can't complete a post-quantum handshake with nodes using the new ones. SemVer impact: none (no release implemented the post-quantum handshake).
- Every protocol vector file and the vendored Wycheproof and hpke-pq sets now run through one vector runner in `meshlink-crypto-sodium`'s tests, on the JVM and the iOS simulator; a vector without a handler fails the build unless it is listed as pending with its ticket. Test-only. SemVer impact: none.

### Fixed

- A link closed as `DUPLICATE_LINK` disconnected at once, so frames the peer had already written on it were lost while the peer reported them sent; a held message could vanish when a restarted peer and this node dialed each other. The losing link now drains: it writes nothing after its `CLOSE` and keeps reading until the peer's `CLOSE` or 10 s (`duplicate-drain-timeout`). No wire change. SemVer impact: none.

- `MeshLinkKit` exported none of SKIE's Swift extensions on its Objective-C classes, because their mangled names compress the module name, so a Swift app calling `start()` failed to link. SemVer impact: none.
- A Mi Note 3 serving the MeshLink GATT service sent its 32-bit MESH UUID in ATT, which ATT forbids, so centrals found no service. The GATT service is now served and looked up under `4D455348-4D4C-4E4B-8000-000000000000`, a 128-bit UUID off the Bluetooth Base UUID that no stack can shorten; advertising and scan filters still use the 32-bit MESH UUID. Nodes from before this change can't open links to nodes after it. SemVer impact: none (no release carried the old service UUID).
- An Android phone with a single advertising instance, such as the Huawei P10 lite, reported `Blocked(Unsupported)` because it reports `isMultipleAdvertisementSupported` false. MeshLink now reports `Unsupported` only when the phone has no Bluetooth LE advertiser while Bluetooth is on. SemVer impact: none.
