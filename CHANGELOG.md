# Changelog

All notable changes to MeshLink are recorded here, in the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) style. Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as [ADR 0019](docs/adr/0019-release-versioning-and-api-compatibility.md) defines them. Every PR adds its entry under "Unreleased" and states its SemVer impact; `./gradlew check` fails when an ABI dump changes without a change here.

## [Unreleased]

### Added

- Committed ABI dumps for `meshlink` and `meshlink-testing`. Both modules are still empty, so the dumps are empty. SemVer impact: none.
- Maven publishing of `meshlink` with a complete POM under The Unlicense, and the `MeshLinkKit` XCFramework for iOS. The `meshlink` klib dump gains its header and still declares nothing public. SemVer impact: none.
- `meshlink-testing` now depends on `meshlink` and `kotlinx-coroutines-test` and holds the internal `VirtualAir` test radio. Its klib dump gains its header and still declares nothing public. SemVer impact: none.
- The node lifecycle API in `ch.trancee.meshlink`: `meshLinkConfig(preset, securityProfile) { meshId = … }.build()` with mesh ID validation and `describe()`, `MeshLink.create(config, platform)`, suspending idempotent `start()` and `stop()`, final `close()`, and `state` (`Stopped`, `Starting`, `Running`, `Blocked(requirements)`, `Stopping`). `SecurityProfile` holds only `Unsecured`; `Preset` names the five built-in scenarios. One node runs per platform radio; another reports `Blocked(RadioInUse)`. On first start a node creates its Ed25519 installation identity, kept in memory for now. `MeshPlatform.ios()` reports `Blocked(Unsupported)` until the Core Bluetooth radio lands. SemVer impact: minor (new API, pre-1.0).
- Discovery: a running node advertises the 16-byte layout `001` payload with its mesh tag and scans for other members of its mesh, keeping those whose mesh tag matches epoch e − 1, e or e + 1 as link candidates. `peers` stays empty until links land. For `meshlink-testing` only, `MeshLink.linkCandidates()` and `radioFailure()` are `@InternalMeshLinkApi` and hidden from Objective-C, and the internal `PlatformPort` gains `radio` and `clock`. SemVer impact: none (no new public behavior; the additions require the internal opt-in).
- Unsecured links: a running node opens a GATT link to each link candidate, selects the highest common protocol version from the peer's capability record and exchanges `PLAIN_HELLO` in clear records. A peer of another mesh gets `CLOSE` `WRONG_MESH`; two links to one neighbor collapse to the one whose central has the lower NodeId; `stop()` sends `CLOSE` `SHUTTING_DOWN` on every link. New public API: `MeshLink.peers: StateFlow<List<Peer>>`, ordered by NodeId; `Peer` with `nodeId`, `reachability`, `secured` and `lastSeen` (`kotlin.time.Instant`); `Reachability.Direct`; and `NodeId`, which prints as lowercase hex and returns its 32 bytes with `toByteArray()`. A peer leaves `peers` when its last link closes. SemVer impact: minor (new API, pre-1.0).
- Direct messages in `Unsecured`: `MeshLink.send(to, payload)` returns `SendResult.Accepted(OutgoingMessage)` or `SendResult.Rejected(reason)` with `RejectionReason` `NotRunning`, `UnknownPeer`, `TooLarge` (above 899 bytes) or `QueueFull` (unwritten payloads at 1 MiB); `awaitSendCapacity()` returns once the queue has room. `OutgoingMessage.status` is a `StateFlow<DeliveryStatus>` of `Queued`, `Held`, `Sent`, `Expired` or `Failed(FailureReason.Stopped)`. Received messages arrive on `messages: Flow<ReceivedMessage>` with the sender's NodeId; a second concurrent collector gets `MeshLinkException.AlreadyCollected`. A message travels only over a direct link to its destination until routing lands, and a message to a known but unlinked peer waits as `Held`. SemVer impact: minor (new API, pre-1.0).
- The Android radio: `MeshPlatform.android(context)` returns the app's one platform, whose Bluetooth LE radio advertises the 16-byte payload (legacy, connectable, 1M, no name), scans for the MESH service, serves the MeshLink GATT service as peripheral, and connects, reads the capability record, subscribes and streams as central. Every GATT request is serialized and retries while the stack is busy, and opening the GATT server retries. Missing Nearby Devices permissions (API 31+) or location permission (API 26 to 30), Bluetooth off, and a phone without Bluetooth LE or its peripheral role show as `Blocked(requirements)`; the requirements are rechecked when Bluetooth changes state and when an activity resumes. MeshLink's manifest declares the permissions; the app requests them. A scan or advertising set that fails after it started now ends discovery as a refusal does. SemVer impact: minor (new API, pre-1.0).
- The iOS radio: on an iPhone, `MeshPlatform.ios()` now returns the app's one platform, whose Core Bluetooth radio advertises the MESH service, scans for it, serves the MeshLink GATT service as peripheral, and connects, reads the capability record, subscribes and streams as central. A connection attempt that hasn't completed after 30 s fails as `PEER_UNREACHABLE`. The Bluetooth prompt can appear at the first `start()`, never at `create()`; the app needs `NSBluetoothAlwaysUsageDescription`. Bluetooth not yet authorized or denied shows as `Blocked(PermissionDenied(Bluetooth))`, Bluetooth off as `Blocked(BluetoothOff)`, and the node stays `Starting` until Core Bluetooth reports its state. The iOS simulator build still reports `Blocked(Unsupported)`. For `meshlink-testing`, the internal `PlatformPort.requirements` is now a `Flow` rather than a `StateFlow`, which changes both ABI dumps. SemVer impact: minor (new behavior, pre-1.0).
- Maven publishing of `meshlink-core` and `meshlink-crypto-sodium` as dependency-only internal artifacts (no API guarantee, outside the SemVer promise), so a consumer that depends on `ch.trancee.meshlink:meshlink` resolves on Android and iOS. `tools/maven-consumer/test.sh` proves it in the macOS CI job. SemVer impact: none.
- A persistent installation identity: the node's Ed25519 seed now survives app restarts. On Android it is sealed with a non-exportable AES-256-GCM Android Keystore key (StrongBox when available) in no-backup storage; on an iPhone it is a `ThisDeviceOnly`, non-synchronizable Keychain item. The iOS simulator build keeps it in memory. A stored identity that can't be read, or a new one that can't be saved, is never replaced: `start()` reports `Blocked(Requirement.IdentityUnavailable)`, `send` returns `Rejected(NotRunning)`, and the next `start()` reads again. The new `MeshLink.resetIdentity()` deletes the stored identity while the node is `Stopped` or `Blocked`, so the next `start()` creates a new NodeId; in any other state it throws the new `MeshLinkException.InvalidState`. For `meshlink-testing`, the internal `IdentityStore` now takes a `CryptoProvider`, may return `null`, and gains `delete()`, which changes both ABI dumps. SemVer impact: minor (new API, pre-1.0).
- Lab apps and tools, never published: `labapp/` holds the scenarios (`direct-message` first) and the Android and iOS host apps; `tools/lab/lab.py` builds, installs and launches them on two lab phones, pulls their JSON Lines results and writes T9 evidence records with pseudonymized Bluetooth addresses. For the lab apps only, `MeshLink.restrictedLinkRole` and `linkRoles` with the new `LinkRole` are `@InternalMeshLinkApi`, which can now mark properties, and hidden from Objective-C; this changes the `meshlink` ABI dumps. SemVer impact: none (the additions require the internal opt-in).
- The internal `CryptoProvider` now has every primitive the `Classical` and `PostQuantum` profiles need: X25519, Ed25519 sign and verify, ChaCha20-Poly1305 (IETF), SHA-256, HKDF-SHA-256, ML-KEM-768 and X-Wing, each key generation and encapsulation also from a seed, with peer-caused refusals as a typed `CryptoResult`. `meshlink-crypto-sodium` binds them on Android and iOS. SemVer impact: none (internal API).
- Tier 2 protocol vectors from a test-only Rust reference in `tools/reference/` (never published): `certificate-signatures.json`, `handshake-hfs.json` and `hpke-seal.json` in `docs/spec/vectors/`, with valid and T10 `invalid` cases. A scheduled, non-required workflow regenerates them and fails on any byte difference. Test-only. SemVer impact: none.

- The internal `IdentityCertificate` in `meshlink-core`: issuing for a node's static keys from the injected `Clock` with a window of at most 24 h, the classical (138 B) and post-quantum (1,354 B) codecs, and validation in the spec's order with a typed `CertificateCheck` whose errors carry the vector codes. It passes the tier 1 `certificate.json`, the `certificate-signing-input` derivation and the tier 2 `certificate-signatures.json`. SemVer impact: none (internal API).
- The internal Noise state machine in `meshlink-core`: `NoiseHandshake` for `Noise_XX_25519_ChaChaPoly_SHA256` and `Noise_XXpsk3_25519_ChaChaPoly_SHA256`, its `split()` into a `NoiseTransport`, and `CipherState` with `Rekey()` and the reserved nonce `2^64 − 1`. Every failure is a typed `NoiseFailure` and closes the handshake or transport. It passes the vendored cacophony vectors for both patterns, handshake and transport. SemVer impact: none (internal API).
- The internal Noise state machine gains the `hfs` patterns with ML-KEM-768, `Noise_XXhfs_25519+MLKEM768_ChaChaPoly_SHA256` and `Noise_XXhfs+psk3_25519+MLKEM768_ChaChaPoly_SHA256`, as the Noise HFS specification defines them. An ML-KEM key that fails the modulus check fails the handshake with `INVALID_PUBLIC_KEY`, and a changed KEM ciphertext fails its tag before decapsulation. It passes every tier 2 `handshake-hfs.json` test byte for byte. SemVer impact: none (internal API).
- Spec: the 30 s clock skew applies on both certificate edges, for sealing and every other use; a certificate is usable while `not_before − 30 s ≤ now < not_after + 30 s` (D-46). SemVer impact: none.

### Changed

- Spec: the post-quantum Noise protocol names now follow the Noise specification: `Noise_XXhfs_25519+MLKEM768_ChaChaPoly_SHA256`, `Noise_XXhfs+psk3_25519+MLKEM768_ChaChaPoly_SHA256` and `Noise_IKhfs_25519+MLKEM768_ChaChaPoly_SHA256` (D-45). The names enter the handshake hash, so nodes using the old names can't complete a post-quantum handshake with nodes using the new ones. SemVer impact: none (no release implemented the post-quantum handshake).
- Every protocol vector file and the vendored Wycheproof and hpke-pq sets now run through one vector runner in `meshlink-crypto-sodium`'s tests, on the JVM and the iOS simulator; a vector without a handler fails the build unless it is listed as pending with its ticket. Test-only. SemVer impact: none.

### Fixed

- `MeshLinkKit` exported none of SKIE's Swift extensions on its Objective-C classes, because their mangled names compress the module name, so a Swift app calling `start()` failed to link. SemVer impact: none.
- A Mi Note 3 serving the MeshLink GATT service sent its 32-bit MESH UUID in ATT, which ATT forbids, so centrals found no service. The GATT service is now served and looked up under `4D455348-4D4C-4E4B-8000-000000000000`, a 128-bit UUID off the Bluetooth Base UUID that no stack can shorten; advertising and scan filters still use the 32-bit MESH UUID. Nodes from before this change can't open links to nodes after it. SemVer impact: none (no release carried the old service UUID).
- An Android phone with a single advertising instance, such as the Huawei P10 lite, reported `Blocked(Unsupported)` because it reports `isMultipleAdvertisementSupported` false. MeshLink now reports `Unsupported` only when the phone has no Bluetooth LE advertiser while Bluetooth is on. SemVer impact: none.
