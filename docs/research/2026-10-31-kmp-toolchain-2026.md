# KMP toolchain, 2026-10-31

Status: research findings only. This note does not record a decision. Every
dependency still needs an E3 rationale and user approval.

## Question

What is the most modern *stable*, mutually compatible (E2) toolchain for MeshLink?
MeshLink is a Kotlin Multiplatform library for Android API 26+ and iOS 15+. It ships
through Maven Central and as an XCFramework via SwiftPM, uses Robolectric host tests,
and has a 100% coverage gate (T3).

The question covers:

- Kotlin, AGP and the KMP Android library plugin, Gradle, and the JDK
- Swift export versus SKIE
- XCFramework and SwiftPM distribution, plus the status of CocoaPods trunk
- Maven Central publishing
- Robolectric, Kover, detekt, Spotless/ktlint, and Dokka
- ABI validation
- UniFFI bindings for KMP
- GitHub Actions versions
- Xcode requirements for iOS 15

## Maturity and maintenance notes

- **Kotlin and Google**: both are healthy. Kotlin releases roughly every 1–2 months.
  AGP 9.3, 9.4, and 9.5 shipped between September and October.
- **SKIE (Touchlab)**: maintained, but trails Kotlin by weeks. Support for 2.4.21
  reached Maven Central 21 days after Kotlin 2.4.21, and the docs are behind the
  source. Each Kotlin upgrade is therefore gated on a SKIE release. SKIE is a compiler
  plugin, so an unsupported Kotlin version fails the build.
- **Swift export**: Alpha, and limited to direct integration. It is not viable for an
  XCFramework distributed through SwiftPM.
- **detekt**: there has been no stable release with Kotlin 2.1+ support for 20 months.
  2.0 has spent over a year in alpha.
- **ktlint**: the 1.x stable line is 11 months old and embeds Kotlin 2.2.21.
- **Dokka**: stable 2.2.0 is 7 months old and its analysis is built on Kotlin 2.3.20-dev.
  2.3.0 is in Beta.
- **ABI validation**: the built-in KGP feature is Experimental and the standalone BCV is
  in maintenance. There is no stable option.
- **Kover**: patch releases are active, but there is no Kotlin/Native coverage.
- **Gobley**: effectively unmaintained for current toolchains. Ubique is active.
- **CocoaPods trunk**: becomes read-only on 2026-12-02.

## Candidate baseline (not a decision)

1. **Core**: Kotlin 2.4.21, AGP 9.3.x (9.3.1 is the documented maximum; 9.3.3 is the
   latest patch), and Gradle 9.7.0. This is the newest combination where every vendor
   documents support. AGP 9.5 and Gradle 9.8 can follow once Kotlin 2.5 widens the
   ranges.
2. **Android**: `com.android.kotlin.multiplatform.library`, compileSdk 37, minSdk 26.
   Run the Gradle daemon on JDK 25 LTS and pin a toolchain; JDK 21 is the fallback if
   Robolectric needs it.
3. **iOS API**: SKIE 0.10.16 (accept that Kotlin upgrades depend on SKIE) and an
   XCFramework built by KGP, plus a `Package.swift` `binaryTarget` (checksum and URL).
   Don't use CocoaPods, and don't use Swift export until it supports XCFrameworks and
   leaves Alpha. Building iOS needs Xcode 26.4; device debugging needs Xcode 26.x for
   iOS 15/16 devices.
4. **Publishing**: vanniktech 0.37.0 to the Central Portal, after confirming it works
   with KGP 2.4.21 and AGP 9.3.
5. **Tests**: Robolectric 4.17, with the API 26 and API 37 android-all jars pinned for
   offline use.
6. **Coverage**: Kover 0.9.11 for JVM and Android. iOS code needs a separate strategy
   (see the open questions).
7. **Quality**: Spotless 8.10.4 with ktlint 1.8.0 (or ktfmt). For detekt there is a
   choice between 2.0.0-alpha.6 (a pre-release) and 1.23.8 (stale); see the open
   questions.
8. **Docs**: Dokka 2.2.0 (DGP v2).
9. **ABI**: the KGP built-in `abiValidation` (Experimental, but it covers KLib, so iOS
   is included) rather than BCV, which is in maintenance.
10. **Rust (only if approved)**: Ubique 1.3.2 with UniFFI 0.32. Avoid Gobley.
11. **CI**: pin the action SHAs listed above.

## Open questions

1. **Coverage for iOS and native code**: Kover can't measure Kotlin/Native. T3 needs
   either native coverage from llvm-cov through the Kotlin/Native toolchain (unverified
   whether it's feasible) or a CI-named exclusion and architecture that keeps logic in
   `commonMain`, measured through JVM and Android tests, with thin iOS shims. This
   needs an ADR.
2. **detekt under E2**: options are (a) adopt 2.0.0-alpha.6 and record a hold with the
   removal condition "2.0.0 stable"; (b) use 1.23.8 without type resolution, if it
   runs on Kotlin 2.4 at all (unverified); or (c) drop detekt and rely on the
   compiler's `-Werror` and ktlint. Each option needs an E2 exception or a Q1
   reinterpretation.
3. **ABI validation stability**: both options are non-stable. Using the Experimental
   KGP feature also needs an E2 hold.
4. **AGP line**: stay on 9.3.x inside the documented ranges, or move to 9.5.0 outside
   them?
5. **Xcode lab setup**: install Xcode 26.4 alongside Xcode 27.x, which raises whether
   Xcode 26.x is supported on macOS 27 (unverified). Also, which iOS 15/16 devices are
   in the lab?
6. **SwiftPM publishing**: put `Package.swift` in the same repo or a separate one, and
   host the XCFramework zip on GitHub Releases or Maven? Use KMMBridge (stale) or a
   hand-written script?
7. **Verification**: confirm by smoke build that vanniktech 0.37.0, Dokka 2.2.0, and
   ktlint 1.8.0 work with Kotlin 2.4.21 and AGP 9.3.x.

## Limitations

- No build was run. Every "unverified" or "⚠️" above is a documentation-level
  finding, not a test result.
- Apple's Xcode support-matrix page did not render the Xcode 26 and 27 rows through
  fetching. The Xcode 27 minimum of iOS 15.0 comes from JetBrains KT-87187, which
  quotes Apple, and is consistent with the Xcode 27 release notes.
- Release dates come from Maven POM `Last-Modified` headers or GitHub `publishedAt`,
  and may differ by about a day from announcements.
- Spotless's default ktlint version was not resolved; it comes from generated
  `KotlinBuildConfig`.
- I didn't check Android Studio and IntelliJ versions.
