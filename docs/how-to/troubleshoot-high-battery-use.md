# Troubleshoot high battery use

Use this guide when MeshLink drains the battery faster than your app can accept. Scanning is MeshLink's largest Bluetooth cost: on the measured Android phone it took about 55 mW while on, against 1 mW for each idle link and next to nothing for advertising ([ADR 0008](../adr/0008-routing-topology-and-density-adaptation.md#amendments)). The checks below look at how often the node scans.

## Collect the evidence

1. Let the node run for at least 10 minutes in the place where the drain happens.
2. Take `meshLink.diagnostics.snapshot()`. Its `densityClass` is the class the node runs in now, and its `counters.events` counts each code since `start()`, including the `Debug` code [`ML2001`](../reference/diagnostics.md#ml2001) when [`diagnostics.debug`](../reference/configuration.md#diagnosticsdebug) is off.
3. Read the `power` and `density` lines in the snapshot's `configuration`.
4. [Export the diagnostics](export-diagnostics.md) of the node, so you can attach them to an issue if the checks below don't help.

## Check how often the node scans

Each [`ML2001`](../reference/diagnostics.md#ml2001) count is one scan window starting or stopping, so half the count is the number of windows. The node scans for 4 s per window and rests between windows as [`power`](../reference/configuration.md#power) sets for its density class.

If [`power`](../reference/configuration.md#power) is `Power.Responsive`, the node rests less to find peers sooner. Choose `Power.Balanced` unless your app needs that discovery speed.

## Check the density class

If [`ML2007`](../reference/diagnostics.md#ml2007) (density class changed) reports `to=Low` in a crowd, the node scans and floods as for a few peers. A low class rests the shortest between scans.

If `ML2007` repeats while the crowd around the phone stays the same, the class flaps. Pin it with `Density.Pinned` in [`density`](../reference/configuration.md#density) to the class the crowd has. Don't pin `DensityClass.Low` in a crowd: it floods everywhere, at about 2 to 4 times the load of the busiest phone.

## If the problem stays

Open an issue with a [diagnostics export](export-diagnostics.md) attached, and the battery use you measured and how. The export holds no key, payload, NodeId, mesh ID or Bluetooth address ([Diagnostics export](../reference/diagnostics-export.md)).
