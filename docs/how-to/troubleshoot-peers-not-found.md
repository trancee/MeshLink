# Troubleshoot peers that aren't found

Use this guide when `MeshLink.peers` stays empty, or misses a phone you expect, after `start()`. It works through the causes from the most common to the rarest, with the [diagnostic code](../reference/diagnostics.md) that points to each.

## Collect the evidence

1. Turn on [`diagnostics.debug`](../reference/configuration.md#diagnosticsdebug) in the configuration, so `meshLink.diagnostics.events` also emits the `Debug` events.
2. Collect `meshLink.diagnostics.events` on both phones from before `start()`, and reproduce the problem.
3. Read `meshLink.state`, and take `meshLink.diagnostics.snapshot()` on both phones. Its `counters.events` counts every code reported since `start()`, including `Debug` codes when `diagnostics.debug` is off.
4. [Export the diagnostics](export-diagnostics.md) of both phones, so you can attach them to an issue if the checks below don't help.

## Check the node can use the radio

If `meshLink.state` is `MeshState.Blocked`, the node waits for each `Requirement` in it: Bluetooth on, or a permission granted. It moves to `Running` by itself once they are met.

If the state is `Running` with `Limitation.CentralOnly`, this phone can't advertise. It still finds peers that advertise, but other phones can't find it, and two central-only phones never link.

If you see [`ML2002`](../reference/diagnostics.md#ml2002) (scan failed), [`ML2005`](../reference/diagnostics.md#ml2005) (advertising failed) or [`ML2008`](../reference/diagnostics.md#ml2008) (GATT service failed), the platform stopped that part of discovery. Turn Bluetooth off and on, close other Bluetooth apps, then call `start()` again.

## Clear leaked scanner registrations on Android

If [`ML2002`](../reference/diagnostics.md#ml2002) carries `platformCode=2` and [`ML8001`](../reference/diagnostics.md#ml8001) appears beside it, Android refused to register the scanner: `SCAN_FAILED_APPLICATION_REGISTRATION_FAILED`. An app, often this one after a crash, left scanner registrations open until the stack ran out of them.

1. Turn Bluetooth off and on.
2. If `ML8001` comes back, restart the phone. A Bluetooth toggle doesn't clear every leaked state.

## Let connect failures with status 133 or 147 retry

If [`ML3003`](../reference/diagnostics.md#ml3003) (connect failed) shows `reason=Transient` with `platformCode=133` or `platformCode=147`, Android's connect failed in a way that often clears on retry:

- 133 is the stack's generic `GATT_ERROR`. It is common on a first connect on every Android phone.
- 147 is `GATT_CONNECTION_TIMEOUT`: the peer didn't answer, because it is out of range or not advertising as connectable.

MeshLink retries a transient failure up to 3 times, so a few of these are normal. If every attempt fails, move the phones closer and turn Bluetooth off and on. Waiting before connecting doesn't help.

## Check both phones belong to the same mesh

If you see [`ML4001`](../reference/diagnostics.md#ml4001) (handshake failed) with `reason=Decrypt`, the phones use different security profiles, mesh IDs or mesh keys. Give every phone of the mesh the same three. With `reason=Certificate`, check that both clocks use the network-provided time.

If you see [`ML3008`](../reference/diagnostics.md#ml3008) (protocol version rejected), the two apps run MeshLink versions that don't share a protocol. Update both apps to the same MeshLink version.

[`ML2006`](../reference/diagnostics.md#ml2006) (stale address) is usually a phone of another mesh or app nearby. If it repeats while a phone of this mesh stays unfound, check that phone's mesh ID and security profile as above.

## Accept the limits of a crowded mesh

In a dense mesh, [`ML3004`](../reference/diagnostics.md#ml3004) (link cap reached) and [`ML4002`](../reference/diagnostics.md#ml4002) (handshake limit) are expected: a node keeps only a few links, and links to other peers as links close. A peer it doesn't link to directly still reaches it through the mesh.

## If the problem stays

Open an issue with a [diagnostics export](export-diagnostics.md) from both phones attached. The export holds no key, payload, NodeId, mesh ID or Bluetooth address ([Diagnostics export](../reference/diagnostics-export.md)).
