Question. In the bearer bake-off, an iPhone X holding 4 incoming links disappeared from every scanner while still reporting itself as advertising. So v1 caps iOS incoming (peripheral-role) links at 3; further links start from the iPhone as central. Does the recommended v1 (UA F+K2 · BA CU, degree 6 / 5 / 5) still meet the criteria?

Model. At 3 incoming links (counting incoming connections in progress), an iPhone refuses further incoming connections. It is also not discoverable: it is absent from every scan, and so from other phones' density estimates, until it drops below 3. Its outgoing links are unchanged. Cells: half-iOS mix, medium static N = 50 and 200, high static N = 200, and the arrival scenario. Both the model calibration and the bake-off calibration. The cap-4 rows are the earlier recheck (same cells, seeds and protocol set; no hiding at 4).

  • Criteria still hold. v1 meets every criterion in all 8 cap-3 combinations of cell and calibration, as at cap 4.   • Refused dials roughly double: 0.36–0.48 per phone per minute (cap 4: 0.17–0.34). Hiding does not stop all of them, because phones also dial peers they learned of through gossip.
  • Busiest phone. It stays below flooding in every cell. Values: 429–964 B/s in the static cells, about the same as cap 4. In arrival with the bake-off calibration it rises to 1,268 B/s (cap 4: 957; flooding 1,501).

The exception is medium senders in arrival with the bake-off calibration: 2.40 s, against 1.41 s at cap 4. That cell has only a few medium senders. With the bake-off calibration, unicast p95 was already above 1 s at cap 4.
  • d = 6 / 5 / 5 still holds. With one slot kept free for newcomers, an iPhone rarely needs more than 2 incoming links, so a cap of 3 seldom binds. No further fix is needed.

Words used here

  • U1: unicast by managed flood. UA: stage C adaptive unicast (flood in the low class, hybrid route-or-short-flood in medium and high). B1: broadcast flood. BA: stage C adaptive broadcast (flood in low, Plumtree tree in medium and high).

  • Stage D v1: UA F+K2 · BA CU. Pre-registered candidate (fixed before the main grid, used in the lifetime and N = 1000 sets): UA S5+F+K1 · BA CU. Stage C adaptive: UA · BA. Flooding everywhere: U1 · B1.
  • p95: 95% of delivered messages arrive within this time. Busiest phone: routing bytes per second sent by the busiest phone. Message lifetime, minimum hold, store-and-forward, hop limit: as in the project glossary.
