# Rekey long-lived links

Status: ready-for-agent
Type: AFK
Blocked by: 28

## Behavior

Secured links rekey on a time and record-count schedule, so one Noise key never protects too much traffic.

- **Frame:** `REKEY` (`0x05`), 1 B, sent only on encrypted links.
- **Sender:** after sending the record that carries `REKEY`, it calls Noise `Rekey()` on its sending cipher state.
- **Receiver:** after processing that record, it calls `Rekey()` on its receiving cipher state. Each direction rekeys independently.
- **Schedule (D-21):** a sender rekeys a direction after 3,600 s or 65,536 records in that direction, whichever comes first. Time comes from the injected `Clock`.
- **Enforcement:** a receiver closes the link with `PROTOCOL_ERROR` if a direction exceeds 131,072 records without a rekey.
- **`Unsecured` receiver (owner decision, 2026-11-13):** drops a `REKEY` frame and records a diagnostic, never closing the link, the same rule as an unknown link-local frame ([link.md, Link-local frame summary](../../../docs/spec/link.md#link-local-frame-summary)).

Ticket 31 checks that rekeying still works across `BEARER_SWITCH`.

## Acceptance criteria

- [ ] The `REKEY` cases in `link-frames.json` pass in the one runner, with a deterministic mutation test.
- [ ] A tier 2 link transport and rekey vector set is generated by the ticket 20 Rust reference and passes in Kotlin: several records, a `REKEY` in each direction, and records after it.
- [ ] A seeded `VirtualAir` test holds a `Classical` and a `PostQuantum` link for 3 virtual hours and shows each direction rekeying every 3,600 s, with direct messages still delivered.
- [ ] A seeded test sends 65,536 records in one direction and shows a rekey before record 65,537.
- [ ] T10: a peer that never rekeys is closed with `PROTOCOL_ERROR` after 131,072 records in a direction, and not before.
- [ ] T10: a `REKEY` before handshake completion fails the handshake. A record encrypted with the old key after a `REKEY` fails to decrypt and closes the bearer.
- [ ] An `Unsecured` receiver drops a `REKEY` frame, records a diagnostic, keeps the link open and still delivers later frames, with a test.
- [ ] Spec change, following [Status and change control](../../../docs/spec/README.md#status-and-change-control): link.md "Rekey" states the `Unsecured` rule; a new D-xx entry in `docs/spec/decisions.md` records it; vectors are regenerated with `python3 tools/spec/gen_vectors.py` if a case changes; `python3 tools/spec/check_spec.py` passes.
- [ ] `./gradlew check` passes with Kover at 100%, and `./gradlew iosSimulatorArm64Test` passes.
