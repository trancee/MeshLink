# Prove the secured profiles and crypto speed on real phones

Status: ready-for-human
Type: HITL
Blocked by: 17, 25

## Behavior

The M3 exit criterion holds on real phones: `Classical` and `PostQuantum` links come up over GATT, carry a direct message, and match the `Unsecured` baseline from ticket 17. The primitives are also timed on the oldest Android and the oldest iPhone in the release set, as ADR 0004 requires.

The agent prepares the scenarios and the benchmark. The owner runs the phones, because they sit in the home lab. Each run becomes a T9 evidence record.

- **Profile runs:** the ticket 17 direct-message scenario, once per profile, on one minimal pair per platform pairing: `pixel6`+`nothing2` (Android↔Android), `pixel6`+`ip15` (Android↔iOS), `ip15`+`ip12mini` (iOS↔iOS). Each pair runs an open and a gated mesh.
- **Crypto benchmark:** a new lab scenario, `crypto-bench`, times each `CryptoProvider` primitive, one full `XX` and one full `XXhfs` handshake per side, on `p10lite` (Android 8.0) and `se2016` (iOS 15.8). It reports the median and the spread over a fixed number of runs.
- **Vectors on device:** the benchmark build also runs the X-Wing A.5 and tier 2 `XXhfs` vectors on both phones and fails on any mismatch.

## Acceptance criteria

- [ ] AFK: `tools/lab/` gains the `crypto-bench` scenario with a timeout, and the lab app runs it on Android and iOS.
- [ ] AFK: the ticket 17 scenario accepts the `Classical` and `PostQuantum` profiles and a mesh key.
- [ ] Owner: each pair above links and exchanges a direct message both ways in all three profiles, open and gated. The radio trace shows no cleartext message body in the secured profiles.
- [ ] Owner: a gated pair with mismatched mesh keys never links, on one Android↔iOS pair.
- [ ] Owner: `crypto-bench` passes on `p10lite` and `se2016`, with every on-device vector matching.
- [ ] `python3 tools/lab/lab.py evidence --run <dir>` writes one T9 record per run under `docs/evidence/`, with handshake time per profile, the benchmark table and the environment metadata. Only aliases appear, and `python3 tools/check_private.py` passes.
- [ ] The record compares each `se2016` result with the prior SE 2016 evidence. The owner accepts or rejects the numbers and handshake times; a rejection returns the trade-off to the owner (ADR 0002 latency safeguard).
- [ ] No retry hides a failure (ADR 0017 decision 13).

python3 tools/lab/lab.py run --scenario crypto-bench --devices p10lite,se2016
